## Proposal: Integrate Content Lifecycle into Main GUI

### Current Situation
We have **two separate GUIs**:
1. **Main GUI** (`/`) — Project/pipeline runner
2. **Content Lifecycle GUI** (`/content.html`) — Standalone content management

### Problem
Content lifecycle is **project-scoped**. Each project has its own content artifacts created by pipelines. Having it as a separate URL breaks the mental model.

### Proposed Integration

**Add Content Lifecycle as a tab within ProjectView:**

```
Main GUI (localhost:5173/)
  └── When you select a project:
       ├── Tab 1: Pipelines (current)
       │    └── List of runnable pipelines
       │
       └── Tab 2: Content Lifecycle (NEW)
            └── Content stages for THIS project's outputs
```

### Why This Makes Sense

✅ **Conceptual clarity**: Content lifecycle lives within projects
✅ **Artifacts = Pipeline outputs**: Content is generated by running pipelines
✅ **Unified workspace**: "What can I run?" + "What did I generate?"
✅ **Project context**: Each project has its own content structure
✅ **Better UX**: One place to manage everything about a project

### Implementation Plan

**1. Update ProjectView to add tabs** (~15 min)
```jsx
// ProjectView.jsx
const [activeTab, setActiveTab] = useState('pipelines');

<div className="flex gap-4 border-b">
  <button onClick={() => setActiveTab('pipelines')}>
    📋 Pipelines ({pipelines.length})
  </button>
  <button onClick={() => setActiveTab('content')}>
    📝 Content Lifecycle
  </button>
</div>

{activeTab === 'pipelines' ? (
  <PipelinesGrid />  // current functionality
) : (
  <ContentApp project={project} />  // embed content lifecycle
)}
```

**2. Update ContentApp to accept project context** (~10 min)
```jsx
// ContentApp.jsx
function ContentApp({ project }) {
  // Load config from: project.path + '/content-stages.yaml'
  // Or: project.path + '/config/content-stages.yaml'
  // Pass project.path to backend API
}
```

**3. Update backend API to accept project path** (~15 min)
```python
# content_app.py
# GET /api/content/config?project_path=/path/to/project
# Load content-stages.yaml from specified project directory
```

**4. Keep standalone URL working** (~5 min)
- `/content.html` still works for testing/direct access
- If no project specified, use CWD (current behavior)

### Total Time Estimate: 45 minutes

### Benefits

- **One GUI to learn** instead of two
- **Natural workflow**: Select project → See pipelines → Run pipeline → View generated content in lifecycle
- **Project isolation**: Each project's content is clearly scoped
- **Backward compatible**: Standalone content GUI still works
