# Proposed issues — drafts, none filed

One directory per target repository. Every file here is a draft for the Captain. These targets
belong to other organisations, so filing any of them is his decision (`project-tracking.md`,
and rule `agent-may-file-issues`); nothing is created with `gh issue create` until he has read
the body and said so.

Delete a draft once its issue is filed — `tmp/` holds throwaway files only, and a draft that
outlives the issue it became is a second copy that drifts.

## bible-technology/alignment-spec

Where the alignment content format is specified (`spec.md`). The Scripture Burrito flavor
page — https://docs.burrito.bible/en/develop/flavors/alignment_flavor.html — points at this
repository for the format itself.

| draft | subject |
|---|---|
| `01-provenance-is-a-chain.md` | `meta` has one `creator` slot; real corpora have produced / published / corrected / copyright-held, and CC BY makes attribution a licence term |
| `02-replace-placeholder-examples.md` | Every example is a placeholder; the one real one uses a non-open text. Replace with real records. **Depends on 03** |
| `03-no-normative-scheme-definitions.md` | `documents[].scheme` is a name with nothing normative to resolve against. Needs a registry, a pattern notation, and a place for semantics |

**Still unconfirmed:** whether these go to `bible-technology/alignment-spec` or
`bible-technology/scripture-burrito`. Both are public and both take issues. Every quotation
in all three drafts comes from `spec.md` in `alignment-spec`, which is why they are filed
here pending the Captain's ruling.

**Held, not abandoned.** The Captain's direction on 2026-09-11 was to discuss these in the
Scripture Burrito Working Group and resolve them there before baking anything into the
specification's examples. These drafts are the discussion material.

## Clear-Bible/Alignments

Public data repository — https://github.com/Clear-Bible/Alignments

`Clear-Bible-Alignments/candidates.md` — eleven measured candidates: the LFS catalogue pointer,
four unparseable TOML sidecars, TOML/JSON attribution disagreeing in 15 of 17 pairs, a file
carrying the wrong corpus, and the scheme declarations that do not match their selectors.

Not a defect and deliberately excluded: `data/eng/alignments/BSB/foo.json` is untracked, so it
is a local stray rather than anything published.

## Clear-Bible/biblealignlib

Biblica's library for this data, and the generator of the files above —
https://github.com/Clear-Bible/biblealignlib

`Clear-Bible-biblealignlib/candidates.md` — seven measured candidates: a fresh clone cannot
`poetry install`, the library points at a repository layout the published data no longer uses,
the test suite needs private repositories, `mypy` is aimed at a directory that does not exist,
and the library implements a different specification document than the one the flavor page
links to.

**Order matters between these two.** Several data defects in `Alignments` are generated by
`biblealignlib` rather than hand-written — the scheme declarations most clearly. Fixing the
generator and regenerating is right; patching the data first would be undone by the next write.

## A caution that applies to everything here

Some alignment data in sibling repositories (`alignments-eng` and the other per-language
repositories) is copyright-restricted and may only be distributed to parties with rights to the
underlying translations. **Nothing from those repositories goes into a public issue, PR, test
fixture or example.** The Matthew 1:1 example used in the alignment-spec drafts is safe on this
count: SBLGNT and BSB are both openly licensed.
