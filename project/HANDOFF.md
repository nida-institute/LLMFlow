## Decisions

### Settled 2026-09-26 — do not reopen

- **The service is called Parallel Passages**, not "cross references". The database carries
  parallels and OT quotations and holds **no allusions**: `MRK 1:6` has one partner, `MAT 3:4`,
  and `2KI 1:8` occurs 0 times. A reader told "cross references" would expect the Elijah echo.
- **A group is returned whole, never intersected.** Returning half of `MRK 1:2-3` would report a
  parallel for text the caller did not ask about while implying the rest was checked.
- **The database is numbered `org`** — all 2,788 `HEB` rows parse under it, 14 refuse under `eng`.
  A request in another scheme is mapped **before** lookup, using the **packaged** mappings rather
  than `~/.sp`, so the reader does not answer differently per machine.
- **#176 does not gate #244.** `steps/llm.py:88` computes `body` for the contract check and
  discards it; the whole file reaches the model. So #176 changes what the model sees and nothing
  about how a `.gpt` is authored. **It gates #255 instead** — replay aligns the prompt file
  against a capture, so if #176 strips at render time the capture shortens.
- **Examples use no defaults** — a default hides from the reader that the value is theirs to
  choose. The example declares `passage` nowhere and names it explicitly in every step;
  `description:` states the required flag.
- **The example teaches explicit variable reference only.** The three other mechanisms —
  an undeclared `--var` reaching a step, `passage: "${passage}"`, derived variables — are
  advanced and are not taught there.
- **The two surfaces ship; `docs/index.json` does not.** A project uses the `sp` CLI and the
  `llmflow` public API, never an `llmflow.*` submodule. `index.json` maps internals, so its
  guidance is engine-only.
